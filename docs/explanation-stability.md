# 片区解释与参数稳定性

2026-11-06新增到MapLibre研究预览；复用MapLibre GL JS、HeatwaterCore、HeatwaterBlockCore，正式Canvas网页与科学栅格输出保持原有行为。

同日后续将真实预览改为[51个主干路片区](planning-blocks.md)并裁切至真实四环边界；本文末尾528单元的结果属于更改前的对照记录，新范围结果见该说明。

## 使用流程

1. 在地图上点击片区，或点击下方核查清单中的片区名称定位。
2. 解释卡展示当前入选情况、有效面积、数据质量、热/水/复合/双高/建筑暴露指标、全域均值与排名。
3. 点击“查看入选频率地图”，查看72组参数下的入选比例；展开片区的72组明细核对依据。
4. 筛选“当前参数入选”“入选频率≥80%”或参数敏感片区，地图和清单同步更新。搜索支持名称与编号。
5. 导出筛选清单CSV，包含全部匹配片区；页面列表仅显示前20项。

权重、阈值滑条仍控制单次分析，调整后地图自动显示当前变化。固定72组合的频率不随单次参数操作改变；切换空间尺度时重新计算并按尺度缓存。后台Worker执行现有计算核心，地图仍可操作，离线HTML无需服务器。

## 筛查规则

片区需要至少9个有效像元、有效覆盖至少80%。符合这两个条件后，片区内“复合分数达到阈值且建筑暴露≥0.6”的像元占有效像元至少20%，即进入候选清单。

20%是第一版探索性筛查口径，尚未用实地观测校准。它与双高像元占比是不同指标：复合分数使用加权热、水分数；双高要求两种分量分别达到阈值。界面的大面积数值仍是分量双高面积，并明确标注。

范围边界截断单独提示，不自动剔除；用户需查看片区是否仅部分落入研究区。少于9个有效像元或覆盖不足80%的单元可以查看现有指标，但不参加候选判定、排名或频率计算。频率为空值，不用0代替。

## 稳定性的含义

热权重取0.30、0.35、0.40、0.45、0.50、0.55、0.60、0.65、0.70；水权重为其补数。阈值取0.50、0.55、0.60、0.65、0.67、0.70、0.75、0.80。共72组，等权计数，包含默认0.55与0.67。

入选频率=入选组合数/72。≥80%标为在多数所测试参数下入选；介于0与80%时提示入选随参数变化。频率为0仅表示在这组参数网格下未入选，不能解释成没有风险。频率不是灾害发生概率，不覆盖输入误差、空间尺度敏感性或模型结构不确定性。

每组参数的排名按高分高暴露像元占比降序，并列竞争排名（如1、1、3），在数据支持充分的片区中计算。排名范围覆盖所有72组，包括该片区未入选的组合。清单按频率降序，再按当前高分高暴露占比、编号排序。

## 解释卡与导出

解释卡排名按各项指标分别降序，限定在支持充分的片区中。全域均值按共同有效像元加权，包含低支持单元中的有效像元，与片区均值的算术平均不同。指标关系仅描述空间差异，不证明因果。

查看上一步地图时，解释卡明确提示其仍展示当前参数，避免混淆。导出的筛选清单始终对应当前参数，包含入选状态、有效像元、覆盖、边界截断、各项指标、入选频率、入选次数、排名范围、全部参数取值与筛查规则；不受列表20行上限限制。

## 构建与验证

沿用[开源接入实验](open-source-pilot.md)的MapLibre依赖安装与打包步骤：

```powershell
python -m scripts.build_maplibre_prototype --data website/data/local.js --output artifacts/opensource-pilot/changchun-maplibre.html
python -m scripts.build_maplibre_prototype --output artifacts/opensource-pilot/maplibre-demo.html
npm test
node website/maplibre-lab/check.cjs
node website/maplibre-lab/research-check.cjs
```

需要GDAL的Python环境。若依赖安装在`website/maplibre-lab`，构建时添加`--vendor website/maplibre-lab`。本地实验使用隔离的`artifacts/maplibre-runtime`。

纯计算测试逐组合与原有像元、片区核心核对，覆盖并列名次、无数据、不足覆盖及恰好20%的入选边界。浏览器检查覆盖后台计算期间调参、解释卡、72组明细、地图和清单筛选一致、CSV、尺度切换、移动端和零HTTP请求。

本次长春概览结果：528个单元、520个支持充分；默认参数下252个候选片区，132个在至少80%的组合下入选。对应上述规则与现有数据，不能直接作为经过验证的治理结论。真实输入及实验产物不随公开仓库分发；公开模拟HTML可独立复现同一工作流。
