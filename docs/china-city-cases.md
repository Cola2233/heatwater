# 八城公开案例制作方案

首批包含长春、北京、天津、上海、广州、深圳、香港、台北。每个案例限定在注明范围的城区样区。体验包的九个模拟片区用于操作教学，真实城市案例各自提供离线 HTML 和数据说明。

| 案例 | 拟用范围 | 制作安排 |
|---|---|---|
| 长春 | 已有四环研究区，51 个主干路片区 | 沿用本地研究成果作计算对照，核清公开版输入后打包 |
| 北京 | 中心城区建成区样区 | 第一个新增样区，验证入库、统计及导出 |
| 天津 | 海河沿线中心城区样区 | 北京流程通过后制作 |
| 上海 | 黄浦江两岸中心城区样区 | 北京流程通过后制作 |
| 广州 | 珠江两岸中心城区样区 | 华南批次 |
| 深圳 | 南山、福田至罗湖的连续建成区样区 | 华南批次，独立设定边界 |
| 香港 | 维港两岸建成区样区 | 海陆分界与山地质量检查 |
| 台北 | 台北盆地中心建成区样区 | 检查云量、河流和盆地边缘 |

范围名称用于选取影像和讨论样区，成品应附具体研究区几何和来源。

## 首轮影像目录检查

用八个样区的经纬度外包框查询公开 Landsat 目录，抽查 2014、2023 年 6–8 月。下表是首批返回结果中 Tier 1 L2SP 场景整景云量 ≤35%、含温度与像元质量波段的不同观测日数。相邻影像行的同一天只计一次。长春与香港的 2023 年结果尚有后续页，表中为已观察到的下限。这是目录初筛，仍需检查样区内的有效像元覆盖。

| 案例 | 2014 年 | 2023 年 |
|---|---:|---:|
| 长春 | 8 | ≥7 |
| 北京 | 2 | 6 |
| 天津 | 5 | 9 |
| 上海 | 2 | 4 |
| 广州 | 0 | 2 |
| 深圳 | 2 | 11 |
| 香港 | 2 | ≥12 |
| 台北 | 1 | 3 |

广州和台北应优先检查完整的 2013–2015 夏季窗口。若还不足以做稳健合成，再依据样区内的云掩膜和观测次数筛选可用场景。

北京中心小样已从两景公开影像生成对齐的温度 GeoTIFF。场景为 `LC08_L2SP_123032_20140819_02_T1` 和 `LC09_L2SP_123032_20230719_02_T1`。样区取 116.34–116.48°E、39.87–39.97°N，输出为 EPSG:32650 的 402×373 格、30 米采样网格。剔除 QA_PIXEL 位 0–5 标记、辐射饱和及无值温度像元后，有效覆盖分别为 99.87% 和 99.89%。结果用于检验影像读取、质控和对齐，正式热环境比较使用多景同季节合成。

## 数据和口径

- **热环境**使用 [Landsat Collection 2 地表温度](https://www.usgs.gov/landsat-missions/landsat-collection-2-surface-temperature)两期同季节合成。优先沿用长春的 2013–2015 和 2021–2023 年夏季窗口，并记录逐景日期、去云规则、观测次数和有效覆盖。目录的整景云量只用于初筛。
- **地表覆盖与变化**可用 [ESA WorldCover 2021](https://esa-worldcover.org/en/data-access)描述土地覆盖。变化指标另用口径一致的两期产品或分类流程，WorldCover 2020 与 2021 的版本差异会影响直接变化估算。
- **水涝代理**用高程、局部低洼和硬化地表等可复现输入。若选用 [Copernicus DEM](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)，保留对应产品署名，说明其为地表高程模型，记录平地和水体处理方式。
- **片区边界**沿用长春的主干路与河流围合思路。道路和水系记录提取日期及许可。采用 [OpenStreetMap](https://www.openstreetmap.org/copyright) 时，按其地图署名和衍生数据条款分别处理。
- **建筑暴露**以具备来源、覆盖和用途说明的建筑功能数据计算。缺建筑用途的案例只能在独立的热水专题模式展示，并由界面隐藏相应的建筑暴露与核查规则，避免将数据缺失当成低暴露。

## 制作顺序和交付

1. 查询八地的热红外场景目录。北京先核算样区的逐像元有效覆盖，再确定合成窗口。
2. 把当前绑定长春的坐标系、案例名称和时间段改为案例配置。用北京样区检查空间对齐、道路分区、分析参数和 CSV 输出，同时对照现有长春基线。
3. 为每个可交付案例打包单文件 HTML、研究区说明、数据来源和处理记录。先验收北京案例，再扩展其余六座城市。长春公开版按已核明的来源和分发范围制作。
4. 发布时附可核查的来源、日期、方法和数据署名。城市间比较需要同时核对时间窗口、共同有效覆盖与归一化口径。

长春研究版在本地运行。各个温度样例和待补数据的进度见[城市案例目录](../cases/README.md)。
